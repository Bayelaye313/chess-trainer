# Décisions prises seul (refonte UX/UI)

1. **Base de la branche** : `redesign` part de `origin/feat/middlegame-academy-noseknowsall` (60ae588) et non de `main` (683a1ac). `main` n'ajoute que le commit de fusion de la PR #1 ; la branche de fonctionnalité contient 10 commits de plus, dont `/rapport/ouvertures/<slug>` et les cours GDR/Najdorf décrits par l'inventaire. L'inventaire (`docs/app-inventory.md`) n'existe que dans 60ae588.
2. **Captures « avant » absentes** : `docs/screens/current/` n'existe sur aucune branche ni sur ce poste (relevé fait sous Windows). Les comparaisons s'appuient sur les mesures chiffrées de l'inventaire (sections 2, 6, 7).
3. **Installation des dépendances** : `npm install` sur le `node_modules` relié (lien symbolique sous Linux, équivalent de la jonction) a été tué faute de mémoire (3 Go) et remplaçait le lien par un dossier. `lucide-react` 1.66.0 et `@radix-ui/react-tabs` 1.2.1 ont été installés dans un dossier isolé puis copiés dans le `node_modules` partagé (ajout pur, React non dupliqué) ; `package.json` et `package-lock.json` mis à jour par `npm install --package-lock-only`.
4. **Polices** : Fraunces (titres) + IBM Plex Sans (texte) + IBM Plex Mono (chiffres, notation), woff2 latins tirés des paquets Fontsource (OFL, licences jointes). Geist supprimée.
5. **Surface « papier »** des commentaires de cours : passée en surface sombre (thème unique exigé par CLAUDE.md). Le panneau clair du graphe d'évaluation est conservé (il encode Blancs/Noirs comme un échiquier).
6. **Rouge de gaffe en texte** : les classes `text-blunder` deviennent `text-danger` (`--status-danger #f07a76`, 6,4:1) ; le jeton `--quality-blunder` reste inchangé pour les fonds, pastilles et cercles.
7. **Voile du dernier coup** : cyan → bleu `rgb(64 140 214 / .34)`, lisible sur les deux teintes de case ; halo cyan du cadre de l'échiquier supprimé.
8. **En-tête** : « NIV. 07 », la jauge XP (68 %) et « Session locale » sont retirés. Ce sont des valeurs écrites en dur dans `nav.tsx` (aucune donnée derrière) ; le niveau réel reste affiché dans l'Académie.
9. **Synchronisation** : la logique de sondage passe de `use-sync-notifier.ts` à `SyncProvider` (`client/features/sync/sync-context.tsx`, `useSyncNotifier` conservé comme adaptateur). Les échecs (réseau, plateforme en erreur pour un pseudo) ne sont plus avalés : pastille « Synchro en échec » dans l'en-tête et message par pseudo dans Réglages. Le texte du toast passe au tutoiement et compte les parties.
10. **Moteur** : délai d'échec affiché après 25 s (`use-engine-timeout.ts`, couche présentation) ; `client/engine/` n'est pas modifié (hors périmètre autorisé).
11. **Réglages** (`/plus`) : la page lit aussi les préférences et la séance du jour (requêtes existantes `getTrainingPreferences`, `getDailySessionState`) pour héberger le formulaire du plan.
12. **Captures** : `deviceScaleFactor` 1 et sans `backdrop-filter` (le navigateur sans GPU de ce poste n'arrivait pas à produire une capture pleine page au-delà). L'en-tête et la barre mobile ont donc un fond plein.
13. **Jouer déplacé sur `/jouer`** : la partie vivait sans URL sur l'accueil. Même module (`usePlayGame` intact). `/jouer?rejouer=1` relance le dernier réglage mémorisé (`localStorage` `chess-trainer:last-bot-setup`) : 1 clic depuis le raccourci « Rejouer » d'Aujourd'hui. La jauge de force des cartes de bot est retirée (décorative) ; le descriptif du bot choisi reste affiché.
14. **Pagination des parties** : `/?page=<n>` redirige vers `/parties?page=<n>` (nouvelle page, recherche comprise) ; l'accueil n'affiche que 5 parties + « Voir tout ».
15. **Séance du jour** : « Continuer » ouvre la prochaine action et enregistre la file de la séance (`sessionStorage` `chess-trainer:seance-queue`). Hors de l'accueil, une barre « Séance du jour n/N · Action suivante » enchaîne les actions sans retour manuel. Les puzzles de la séance s'ouvrent sur l'accueil via `/?puzzle=<id>`. Les actions suivantes sont listées sans être cliquables une à une (une seule action principale). « Impact N » devient « Priorité N » (même info-bulle).
16. **Cartes retirées de l'accueil** : « Corrigez vos gaffes » (doublon de S'entraîner, remplacé par le raccourci « Réviser » avec le compteur) et « Synthèse du rapport récent » (doublon de Progrès). Composants supprimés, données toujours visibles dans `/entrainer` et `/rapport`.
17. **Noms des bots** : les parties enregistrent le libellé du profil avec emoji (`core/chess/bot-profiles.ts`, non modifiable) ; l'interface l'affiche sans emoji (`displayOpponentName`).
18. **`lib/labels.ts`** : seules des classes de couleur changent (`text-blunder` → `text-danger`), aucun texte ; `labels.test.ts` inchangé.
19. **Vitest** : 18 tests serveur échouent à l'identique sur le commit de base 60ae588 et sur la branche (même copie de base) : ils dépendent des tables `imported_opening_lines` / `imported_traps` et de lots de puzzles absents de la base de ce poste (47 parties, aucun import Lichess). Aucun test lié à l'interface n'échoue.
20. **Ouvertures — « Mon répertoire »** : cartes curatées hors `OFF_REPERTOIRE_COURSE_IDS`, groupées par camp (le filtre « Les deux camps / Blancs / Noirs » devient ce regroupement ; la recherche reste). « Autres ouvertures » (replié) = familles `lichess-*` **et** les 4 cours hors répertoire (Slave, Dragon, Caro-Kann, Alapine), signalés « Cours complet ». Pastilles : *Cours complet* (cours enregistré), *Cours à venir* (ouverture curatée sans cours), *Carte seule* (famille Lichess, drill seul).
21. **Fiche ouverture** : onglets Cours · Drill · Mes parties · Mes erreurs (Radix). Onglet par défaut : Drill si l'URL vise le drill (`?drill=`, `?side=`, `?mode=sans-guide`), sinon Cours s'il existe. Le drill reste monté quand on change d'onglet. Endurance, progression de l'étude et sparring sont des blocs repliables du Drill. Un seul lien vers le cours (« Commencer / Reprendre le cours ») ; le bouton de la zone d'endurance qui menait au cours ouvre désormais l'onglet Cours. Un seul retour (« ← Ouvertures », en haut à gauche) : le « ← Retour » du drill est retiré.
22. **Mes parties (fiche)** : la page lit `getCourseGamesOverview()` (requête existante) pour les ouvertures à cours et renvoie vers `/rapport/ouvertures/<id>`.
23. **Reprise du cours** : le lecteur signale chaque changement de position (`onPositionChange`, prop ajoutée à `CourseTreeViewer`) ; position par ouverture et dernier cours en `localStorage`. Sans `?chapitre=&noeud=`, le cours reprend à la dernière position ; la fiche propose « Reprendre le cours (chapitre n) » et Aujourd'hui « Reprendre le cours : … ».
24. **Textes renommés (tests mis à jour dans le même commit)** : `opening-stats.ts` — « Verrouiller les réflexes (Mode Sans Guide - Début) » → « Rejouer la ligne sans aide dès le 1er coup » ; « Lancer le simulateur de survie (Milieu de jeu) » → « Travailler le milieu de jeu dans le cours » (`opening-stats.test.ts`). Radar : « Vos Forteresses / Vos Zones de Danger » → « Tes forteresses / Tes zones de danger ». « Vision Moteur » → « Flèche du moteur » ; « Mode Entraînement » → « Drill ».
